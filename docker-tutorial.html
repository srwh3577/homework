1. 什麼是 Docker？

Docker 是一個容器化（Containerization）平台，把應用程式連同它執行所需的一切 ——程式碼、執行環境、函式庫、設定——打包成一個標準化的「容器」，讓它在任何裝了 Docker 的機器上都能用一模一樣的方式執行。

它解決的經典痛點是那句工程師名言：

「在我的電腦上明明可以跑啊！」——程式在開發機正常，部署到測試／正式環境卻壞掉， 因為兩邊的作業系統、套件版本、環境變數不一致。Docker 把「環境」也一起打包，從此環境一致、隨處可跑。

使用 Docker 的好處：

  • 環境一致：開發、測試、正式環境用同一個映像，消除「環境差異」問題。
  • 輕量快速：容器共享主機核心，啟動只要秒級，體積比虛擬機小得多。
  • 隔離性：每個容器有獨立的檔案系統、網路、行程空間，彼此不干擾。
  • 易於擴展與部署：映像可推到 Registry，任何機器拉下來就能跑，是微服務與 CI/CD 的基石。

2. 容器 vs 虛擬機（VM）

要理解 Docker 為何輕量，先看它和傳統虛擬機在架構上的差別。

比較項目虛擬機（VM）容器（Container）
隔離層級硬體層（各自完整 OS）行程層（共享主機核心）
體積GB 級MB 級
啟動速度數十秒到分鐘秒級甚至更快

兩者不是互斥：實務上常見「在 VM 裡跑 Docker」。VM 提供強隔離與資源切分，容器在其中提供輕量、快速的應用封裝。

核心術語對照表

術語說明
Docker EngineDocker 的核心，包含背景服務 Daemon（dockerd）、REST API、以及命令列 Client（docker）。
Image（映像）一個唯讀的模板，包含執行應用所需的檔案系統與設定。由多個層（layer）疊成。例如 nginx:1.25。
Container（容器）映像的執行實例。在映像之上加一個可寫層後跑起來，就是一個容器。同一映像可開出多個容器。
Registry（倉庫）存放與分發映像的服務。Docker Hub 是預設的公開 Registry，企業也可自架私有 Registry。
Repository / Tag映像的命名與版本，格式 名稱:標籤，如 node:18-alpine。不指定標籤預設為 latest。
Dockerfile一份文字腳本，定義「如何一步步建出一個映像」。
Volume（資料卷）Docker 管理的持久化儲存，讓資料在容器刪除後仍保留。

4. Image 與 Container 的關係

這是最重要、也最常被搞混的觀念。一句話：Image 是模板（class），Container 是實例（object）。 就像程式裡用一個類別 new 出多個物件，你也能用同一個映像跑出多個容器。

flowchart LR DF["Dockerfile"] -->|"docker build"| IMG["Image
(唯讀模板)"] REG["Docker Hub"] -->|"docker pull"| IMG IMG -->|"docker run"| C1["Container 1"] IMG -->|"docker run"| C2["Container 2"] IMG -->|"docker run"| C3["Container 3"]
圖 4-1　映像可由 Dockerfile 建出或從 Registry 拉取；一個映像能跑出多個彼此獨立的容器
  • Image 是唯讀的：一旦建好就不會改變，所以可重現、可分發。
  • Container 在 Image 上加一個「可寫層」：容器執行時寫入的檔案都落在這層，刪除容器時這層也消失（所以要持久化資料得用 Volume，見第 10 節）。
  • 多個容器共用底層唯讀映像層，各自只佔用自己那薄薄的可寫層，因此非常省空間。
類比：Image 像「光碟母片」或「程式安裝檔」，Container 像「裝好正在執行的程式」。母片不變，可以裝很多份。

6. Container 生命週期

容器從建立到刪除，會在幾個狀態間轉換，每個轉換對應一個 docker 指令：

stateDiagram-v2 Created: 已建立 Created Running: 執行中 Running Paused: 已暫停 Paused Stopped: 已停止 Stopped [*] --> Created: docker create Created --> Running: docker start [*] --> Running: docker run Running --> Paused: docker pause Paused --> Running: docker unpause Running --> Stopped: docker stop / kill Stopped --> Running: docker start Stopped --> [*]: docker rm Running --> [*]: docker rm -f
圖 6-1　容器生命週期狀態機：注意「停止」不等於「刪除」
最常見的誤解：docker stop 只是停止容器，它還在（用 docker ps -a 看得到），可以再 start。 只有 docker rm 才是刪除。另外，docker run 每次都建立全新容器—— 如果你想回到剛剛那個容器，要用 docker start，而不是再 run 一次。

7. Dockerfile 與映像分層

Dockerfile 是一份「建構腳本」，每一行指令告訴 Docker 要做什麼。以一個 Node.js 應用為例：

# 1. 指定基礎映像（這一層是別人建好的）
FROM node:18-alpine

# 2. 設定容器內的工作目錄
WORKDIR /app

# 3. 先只複製依賴清單（為了善用快取，見下一節）
COPY package*.json ./

# 4. 安裝依賴
RUN npm ci --omit=dev

# 5. 再複製其餘原始碼
COPY . .

# 6. 宣告應用使用的埠（僅文件用途，不會自動發布）
EXPOSE 3000

# 7. 容器啟動時執行的預設指令
CMD ["node", "server.js"]

常用 Dockerfile 指令

指令作用
FROM指定基礎映像，每個 Dockerfile 的起點
WORKDIR設定後續指令的工作目錄
COPY / ADD把檔案複製進映像（ADD 多了解壓縮、抓 URL 功能，一般優先用 COPY）
RUN在建構時執行指令（如裝套件），會產生新的一層
ENV設定環境變數
EXPOSE宣告容器監聽的埠（文件性質，實際對外仍需 -p）
CMD容器啟動時的預設指令，可被 docker run 後面的指令覆蓋
ENTRYPOINT固定的進入點，run 後面的參數會當成它的引數

映像是一層一層疊出來的

Dockerfile 中每一個 FROM / RUN / COPY 指令都會產生一層唯讀的 layer，疊起來就是最終映像。容器啟動時再在最上面加一個可寫層：

可寫層（Container Layer）容器執行時寫入處 · 刪除即消失
CMD ["node", "server.js"]設定中繼資料
COPY . .Layer
RUN npm ci --omit=devLayer
COPY package*.json ./Layer
FROM node:18-alpine基礎映像層
↑ 由下往上疊：下層唯讀且可被多個映像／容器共用，最上層才是容器專屬的可寫層
為什麼要懂分層？ 因為分層直接影響兩件事：映像體積（層越多越雜越肥）與 建構速度（沒變的層能直接重用快取）。下一節詳談快取。

8. Build 快取機制

Docker build 時會逐層檢查：如果某層的指令與輸入都和上次一樣，就直接重用快取，不重跑。 但只要某一層變了，它「之後」的所有層都得重建。

flowchart TB A["開始 build 第 N 層"] --> B{"這層的指令與輸入
和上次相同嗎？"} B -->|"相同"| C["命中快取
直接重用，跳過執行"] B -->|"不同"| D["快取失效
重新執行這一層"] C --> E{"還有下一層嗎？"} D --> F["這層之後的所有層
都必須重建"] F --> E E -->|"有"| A E -->|"沒有"| G["build 完成"]
圖 8-1　build 快取逐層判斷：一旦某層失效，後續層全部連鎖重建

實務技巧：把「不常變的」放前面

這就是為什麼上一節的 Dockerfile 要先 COPY package*.json 再 RUN npm ci，最後才 COPY . .：

✅ 好順序

COPY package*.json ./
RUN npm ci
COPY . .

改原始碼時，package.json 沒變 → 依賴層命中快取，不必重裝套件，build 飛快。

❌ 壞順序

COPY . .
RUN npm ci

任何原始碼一改，COPY . . 就失效 → 後面的 npm ci 每次都重裝，奇慢。

Multi-stage build：讓最終映像更小

用多個 FROM 分階段：在「建構階段」編譯／安裝，只把最終產物複製到乾淨的「執行階段」，把編譯工具等通通丟掉。

# --- 建構階段：安裝依賴 ---
FROM node:18-alpine AS deps
WORKDIR /app
COPY package*.json ./
RUN npm ci --omit=dev

# --- 執行階段：只拿需要的東西 ---
FROM node:18-alpine
WORKDIR /app
COPY --from=deps /app/node_modules ./node_modules
COPY . .
USER node
EXPOSE 3000
CMD ["node", "server.js"]
搭配 .dockerignore 檔（排除 node_modules、.git、.env 等），可避免把無關檔案塞進映像，同時提升快取命中率。

9. 常用 CLI 指令速查

映像（Image）

# 從 Docker Hub 拉取映像
docker pull nginx:1.25

# 用當前目錄的 Dockerfile 建映像並打標籤
docker build -t myapp:1.0 .

# 列出本地映像 / 刪除映像
docker images
docker rmi myapp:1.0

容器（Container）

# 背景跑一個 nginx，映射埠、命名
docker run -d --name web -p 8080:80 nginx

# 看執行中 / 全部（含已停止）的容器
docker ps
docker ps -a

# 停止、啟動、重啟、刪除
docker stop web
docker start web
docker rm web          # 要先停止；強制刪除加 -f

除錯與互動

# 看容器的日誌（-f 持續跟隨）
docker logs -f web

# 進到執行中的容器裡開一個 shell
docker exec -it web sh

# 清理用不到的映像、容器、網路（釋放空間）
docker system prune

10. Volume 與資料持久化

容器的可寫層會隨容器刪除而消失。所以資料庫、上傳檔案這類需要長期保存的資料， 絕對不能只放在容器裡，必須掛到容器外。Docker 提供兩種主要做法：

/var/lib/docker/volumes/db-data
(Docker 自己管理)"] B["Bind Mount
/home/user/data
(你指定的主機目錄)"] end P -->|"Volume：推薦"| V P -->|"Bind Mount"| B
圖 10-1　Volume 由 Docker 管理（推薦）；Bind Mount 直接對應主機上的指定目錄
Volume（資料卷）Bind Mount（綁定掛載）
儲存位置由 Docker 管理（/var/lib/docker/volumes）主機上任意指定路徑
建立方式-v db-data:/data-v /home/user/data:/data
適合場景資料庫、正式環境資料（可攜、好備份）開發時即時同步原始碼到容器
可攜性高，與主機目錄結構無關低，依賴主機路徑
# 建立並使用 volume（資料持久化）
docker volume create db-data
docker run -d -v db-data:/var/lib/postgresql/data postgres:16

# 開發時用 bind mount 即時同步程式碼
docker run -d -v "$(pwd)":/app node:18 npm run dev
新手最痛的坑：把資料庫直接跑在容器裡卻沒掛 Volume，某天 docker rm 一下，所有資料瞬間蒸發。正式環境的有狀態服務，務必掛 Volume。

11. 網路（Network）

容器預設是隔離的，要讓「外部存取容器」或「容器之間互通」，就要靠 Docker 網路。最常用的是 bridge（橋接）模式。

graph TB EXT["外部 / 瀏覽器"] subgraph HOST["Host 主機"] PORT["Host Port 8080"] subgraph BR["自訂 bridge 網路 my-net"] C1["容器 web
監聽 :3000"] C2["容器 db
監聽 :5432"] end end EXT -->|"連 http://host:8080"| PORT PORT -->|"-p 8080:3000 映射"| C1 C1 -->|"用容器名 db 直接連線"| C2
圖 11-1　外部透過埠映射進到 web；同一網路內的容器可用「容器名稱」當主機名互連
網路模式說明
bridge（預設）容器接到虛擬橋接網路。建議自建網路（docker network create），同網路內可用容器名稱當 DNS 互連。
host容器直接共用主機網路，不做隔離與埠映射，效能高但少了隔離。
none完全沒有網路，最高隔離。
埠映射 -p 主機埠:容器埠 是讓外部世界進入容器的橋樑。沒做映射，容器內的服務從主機外是連不到的。

12. Docker Compose 多容器編排

真實應用通常不只一個容器（例如 web + 資料庫 + 快取）。一個個手動 docker run 又長又容易錯。 Docker Compose 讓你用一份 compose.yaml 宣告所有服務，一個指令全部拉起。

flowchart TB Y["compose.yaml"] -->|"docker compose up -d"| ENG["Docker"] ENG --> NET["建立專屬網路"] ENG --> WEB["啟動 web 服務"] ENG --> DB["啟動 db 服務"] ENG --> VOL["建立 volume db-data"] WEB -.->|"同一網路，用服務名互連"| DB DB --- VOL
圖 12-1　一份 YAML 描述整套應用，Compose 幫你建網路、起容器、掛 volume
services:
  web:
    build: .                       # 用當前目錄 Dockerfile 建映像
    ports:
      - "8080:3000"               # 主機 8080 → 容器 3000
    environment:
      - DATABASE_URL=postgres://user:pass@db:5432/app
    depends_on:
      - db                          # 先起 db 再起 web

  db:
    image: postgres:16-alpine
    environment:
      - POSTGRES_USER=user
      - POSTGRES_PASSWORD=pass
      - POSTGRES_DB=app
    volumes:
      - db-data:/var/lib/postgresql/data   # 持久化資料庫

volumes:
  db-data:

常用 Compose 指令：

docker compose up -d        # 背景啟動全部服務
docker compose ps           # 看服務狀態
docker compose logs -f web  # 跟隨某服務日誌
docker compose down         # 停止並移除容器與網路（加 -v 連 volume 一起刪）
關鍵優勢：Compose 自動建立一個專屬網路，服務之間可直接用服務名稱（上例的 db）互相連線，不必管 IP。

13. 實戰範例與最佳實踐

從開發到部署的完整流程

flowchart LR DEV["原始碼 + Dockerfile"] -->|"docker build"| IMG["Image"] IMG -->|"docker push"| HUB["Registry
Docker Hub"] HUB -->|"docker pull"| SRV["部署伺服器"] SRV -->|"compose up -d"| PROD["執行中的容器"]
圖 13-1　典型的容器化交付流程：build → push → pull → run，這也是 CI/CD 的骨架

✅ 最佳實踐

  • 用官方、輕量的基礎映像（如 -alpine 版本）。
  • 善用 multi-stage build 縮小映像體積。
  • 一定要寫 .dockerignore。
  • 把不常變的指令放 Dockerfile 前面，最大化快取。
  • 固定明確的版本標籤（node:18.20），別只用 latest。
  • 一個容器專注做一件事（單一職責）。
  • 用 USER 以非 root 身份執行，提升安全。
  • 有狀態資料一律掛 Volume。
  • 密碼／金鑰用環境變數或 secrets，別寫進映像。

⚠️ 常見陷阱

  • 資料沒掛 Volume，刪容器就資料全失。
  • COPY . . 把 node_modules、.git 一起包進去，映像爆肥。
  • 把快取友善的指令順序寫反，每次都重裝依賴。
  • 只用 latest，導致部署不可重現。
  • 忘了 -p 映射埠，外部連不到服務。
  • 混淆 run 與 start：每次 run 都是新容器。
  • 把多個服務硬塞進同一個容器，難維護、難擴展。
  • 映像裡寫死密碼，推上 Hub 後外洩。
學習路徑建議：先 docker run 跑起官方 nginx／postgres 玩一玩、用 docker ps / logs / exec 觀察； 接著替自己的小專案寫一份 Dockerfile 並 build；理解分層與快取後，用 multi-stage 優化體積； 最後用 Docker Compose 把 web + 資料庫串起來。每一步都動手敲指令，觀念會牢固得多。
