1. 為什麼需要 Lambda 與 Stream

Java 8 引入 Lambda 與 Stream，最大的改變是讓我們從命令式（怎麼做）寫法， 轉向宣告式（要什麼）寫法。看一個例子——找出清單中所有偶數、平方後排序：

傳統命令式：一步步指揮

List<Integer> result = new ArrayList<>();
for (Integer n : nums) {
    if (n % 2 == 0) {
        result.add(n * n);
    }
}
Collections.sort(result);

Stream 宣告式：描述意圖

List<Integer> result = nums.stream()
    .filter(n -> n % 2 == 0)
    .map(n -> n * n)
    .sorted()
    .toList();

宣告式寫法的好處：

  • 可讀性高：一眼看出「過濾→轉換→排序」的意圖，不必追蹤迴圈與暫存變數。
  • 少出錯：沒有手動管理索引、暫存集合的機會。
  • 易平行化：把 stream() 換成 parallelStream() 就能多核處理（第 13 節）。
兩者的橋樑：Stream 的每個操作（如 filter、map）都接收一個函式當參數， 而 Lambda 正是用來簡潔地寫出這些函式。所以要先懂 Lambda，才能玩轉 Stream。

2. 函式介面（Functional Interface）

Lambda 的本質，是函式介面的一個實例。所謂函式介面，就是 只有「一個」抽象方法的介面（可以再加 default / static 方法）。 可用 @FunctionalInterface 標註，編譯器會幫你檢查是否符合。

flowchart LR FI["函式介面
只有一個抽象方法
int operate(int a, int b)"] -->|"用 Lambda 提供實作"| L["(a, b) -> a + b"] L -->|"賦值給介面型別"| V["Calculator add = ..."] style FI fill:#f0ebfb,stroke:#6d4ad6 style L fill:#e6f4ec,stroke:#1f9d57
圖 2-1　Lambda 就是「那個唯一抽象方法」的實作；編譯器靠介面推斷它的型別
// @FunctionalInterface 不是必需，但建議加，編譯器會檢查
@FunctionalInterface
interface Calculator {
    int operate(int a, int b);   // 唯一的抽象方法
}

// 用 Lambda 提供不同實作
Calculator add = (a, b) -> a + b;
Calculator mul = (a, b) -> a * b;

System.out.println(add.operate(3, 4));   // 7
System.out.println(mul.operate(3, 4));   // 12
你早就用過函式介面了！Runnable（run）、Comparator（compare）、 Callable（call）都是只有一個抽象方法的函式介面，因此都能用 Lambda 來寫。

3. Lambda 語法

Lambda 的基本結構是 (參數列) -> 主體。從匿名內部類別演進過來，能省的都省掉：

// 舊寫法：匿名內部類別，樣板程式碼一大堆
Runnable r1 = new Runnable() {
    @Override
    public void run() {
        System.out.println("Hello");
    }
};

// Lambda：同樣的事，一行搞定
Runnable r2 = () -> System.out.println("Hello");

各種語法形式

() -> 42                       // 無參數，回傳 42
x -> x * x                     // 單一參數可省略括號
(x, y) -> x + y                // 多參數
(int x, int y) -> x + y        // 顯式宣告參數型別
(x, y) -> {                    // 區塊主體：有大括號就要自己 return
    int sum = x + y;
    return sum;
}
情況寫法
沒有參數一定要有空括號 () -> ...
單一參數可省略括號：x -> ...
單行主體不用 {} 與 return，運算式結果即回傳值
多行主體用 {} 包住，需要回傳時自己寫 return
變數捕獲規則：Lambda 能存取外部區域變數，但該變數必須是 effectively final（實質不可變——賦值後不再更動）。這是因為 Lambda 可能在別的時間／執行緒執行，捕獲的是值而非可變參照。

4. 常用內建函式介面

java.util.function 套件提供了一組常用的函式介面，不必每次自己定義。記住四個核心：

介面方法簽章用途
Function<T,R>applyT → R把輸入轉換成另一種輸出
Predicate<T>testT → boolean條件判斷（過濾用）
Consumer<T>acceptT → void消費一個值，無回傳（如印出）
Supplier<T>get() → T不需輸入，提供一個值
BiFunction<T,U,R>apply(T,U) → R兩個輸入轉一個輸出
UnaryOperator<T>applyT → T輸入輸出同型別
BinaryOperator<T>apply(T,T) → T兩個同型別合併成一個
import java.util.function.*;

Function<Integer, Integer> square  = x -> x * x;            // T -> R
Predicate<Integer>        isEven  = n -> n % 2 == 0;       // T -> boolean
Consumer<String>          printer = s -> System.out.println(s); // T -> void
Supplier<Double>          rnd     = () -> Math.random();       // () -> T
BiFunction<Integer, Integer, Integer> add = (a, b) -> a + b;

System.out.println(square.apply(5));   // 25
System.out.println(isEven.test(4));    // true
printer.accept("hi");                  // hi
System.out.println(add.apply(2, 3));   // 5
避免裝箱開銷：處理基本型別時，優先用特化版本如 IntPredicate、ToIntFunction、IntUnaryOperator， 免去 int 與 Integer 之間反覆裝箱／拆箱。

5. 方法參考（Method Reference）

當 Lambda 只是「呼叫一個既有方法」時，可用 :: 進一步簡化成方法參考，更精簡也更易讀。 例如 s -> s.toUpperCase() 可寫成 String::toUpperCase。

種類Lambda 寫法方法參考
靜態方法s -> Integer.parseInt(s)Integer::parseInt
特定物件的實例方法x -> System.out.println(x)System.out::println
特定型別的任意物件方法s -> s.toUpperCase()String::toUpperCase
建構子() -> new ArrayList<>()ArrayList::new
Function<String, Integer> parse = Integer::parseInt;      // 靜態方法
Consumer<String>          print = System.out::println;     // 特定物件實例方法
Function<String, String>  upper = String::toUpperCase;     // 任意物件實例方法
Supplier<List<String>>     maker = ArrayList::new;           // 建構子

// 搭配 Stream 特別好讀
names.stream().map(String::toUpperCase).forEach(System.out::println);

6. Stream 是什麼？管線概念

Stream（串流）不是資料結構，它不儲存資料；它是對某個資料來源的一串運算管線（pipeline）描述。 一條 Stream 管線固定由三部分組成：

flowchart LR SRC["資料來源
List / 陣列 / ..."] -->|"stream()"| F["filter
中間操作"] F --> M["map
中間操作"] M --> SO["sorted
中間操作"] SO --> C["collect
終端操作"] C --> R["結果
List / 值 / ..."] style F fill:#f0ebfb,stroke:#6d4ad6 style M fill:#f0ebfb,stroke:#6d4ad6 style SO fill:#f0ebfb,stroke:#6d4ad6 style C fill:#e6f4ec,stroke:#1f9d57,color:#0f6b3a style R fill:#fcefe2,stroke:#e07b2b,color:#b85f17
圖 6-1　Stream 管線：來源 → 0~n 個中間操作（紫）→ 剛好 1 個終端操作（綠）→ 結果
  1. 來源（Source）：集合、陣列、I/O、產生器等。
  2. 中間操作（Intermediate）：如 filter、map。回傳新的 Stream，可串接、惰性（先不執行）。
  3. 終端操作（Terminal）：如 collect、forEach。回傳非 Stream 的結果，觸發整條管線真正執行。

Stream 的幾個重要性質：

  • 不修改來源：原本的 List 不會被動到，產生的是新結果。
  • 只能消費一次：一條 Stream 被終端操作用過就「關閉」了，再用會丟 IllegalStateException。
  • 可以無限：搭配 limit 處理無限資料流。

7. 建立 Stream 的方式

// 1) 從集合（最常見）
List<String> list = List.of("a", "b", "c");
Stream<String> s1 = list.stream();

// 2) 直接給定值
Stream<Integer> s2 = Stream.of(1, 2, 3);

// 3) 從陣列
int[] arr = {1, 2, 3};
IntStream s3 = Arrays.stream(arr);

// 4) 數字範圍（基本型別流，無裝箱）
IntStream s4 = IntStream.range(0, 5);        // 0,1,2,3,4（不含 5）
IntStream s5 = IntStream.rangeClosed(1, 5);  // 1,2,3,4,5（含 5）

// 5) 無限流 + limit（一定要有 limit 收斂）
Stream<Integer> s6 = Stream.iterate(1, n -> n * 2).limit(10); // 1,2,4,8,...
Stream<Double>  s7 = Stream.generate(Math::random).limit(3);
基本型別流（IntStream、LongStream、DoubleStream）提供 sum()、average()、max() 等方便方法， 並避免裝箱。物件流可用 mapToInt(...) 轉成它們。

8. 中間操作

中間操作都回傳新的 Stream，所以能一個接一個串起來，且在終端操作前不會真正執行。

操作作用
filter(Predicate)保留符合條件的元素
map(Function)把每個元素轉換成另一個（一對一）
flatMap(Function)把每個元素展開成一個流，再攤平合併（一對多）
distinct()去除重複（依 equals）
sorted() / sorted(Comparator)排序
limit(n) / skip(n)取前 n 個 / 跳過前 n 個
peek(Consumer)窺視每個元素（主要用於除錯，勿放業務邏輯）
List<String> result = Stream.of("apple", "banana", "cherry", "avocado")
    .filter(s -> s.startsWith("a"))   // 留下 a 開頭：apple, avocado
    .map(String::toUpperCase)          // 轉大寫：APPLE, AVOCADO
    .sorted()                          // 排序
    .toList();                         // [APPLE, AVOCADO]

map vs flatMap：最容易混淆的一組

map 是一對一轉換；flatMap 則把「巢狀結構」攤平成單層。

map： "a,b""c,d" — map(split) → ["a","b"]["c","d"] 仍是巢狀 Stream<String[]>
flatMap： "a,b""c,d" — flatMap → "a""b""c""d" 攤平成 Stream<String>
圖 8-1　map 保留巢狀層次；flatMap 把每個子流「拆開倒進」同一條流
List<List<Integer>> nested = List.of(
        List.of(1, 2), List.of(3, 4), List.of(5));

List<Integer> flat = nested.stream()
    .flatMap(List::stream)   // 把每個子 List 變成元素流再攤平
    .toList();               // [1, 2, 3, 4, 5]

9. 終端操作

終端操作觸發整條管線執行並產生最終結果（值、集合或副作用）。一條 Stream只能有一個終端操作。 如何分辨中間／終端？看回傳值：

惰性，可繼續串接"] Q -->|"回傳值 / 集合 / Optional / void"| TER["終端操作
觸發執行，管線結束"] style INT fill:#f0ebfb,stroke:#6d4ad6 style TER fill:#e6f4ec,stroke:#1f9d57,color:#0f6b3a
圖 9-1　判斷訣竅：回傳 Stream 的是中間操作，否則是終端操作
操作作用回傳
forEach(Consumer)對每個元素執行動作void
collect(Collector)收集成 List/Set/Map 等集合
toList() (Java 16+)收集成不可變 ListList
reduce(...)歸約成單一值值 / Optional
count()元素個數long
min/max(Comparator)最小 / 最大Optional
anyMatch/allMatch/noneMatch是否符合條件（短路）boolean
findFirst/findAny取一個元素（短路）Optional
List<Integer> nums = List.of(1, 2, 3, 4, 5, 6);

long cnt   = nums.stream().filter(n -> n > 3).count();          // 3
int  sum   = nums.stream().mapToInt(Integer::intValue).sum();   // 21
boolean any = nums.stream().anyMatch(n -> n > 5);             // true
Optional<Integer> first = nums.stream()
        .filter(n -> n % 2 == 0).findFirst();                   // Optional[2]

10. 惰性求值與執行流程

這是 Stream 最關鍵、也最反直覺的機制。許多人以為管線是「先 filter 完全部，再 map 完全部」—— 錯！實際上每個元素是一個一個「縱向」走完整條管線，而且終端操作不呼叫前，中間操作根本不動。

flowchart TB S["取下一個元素"] --> F{"filter 條件成立？"} F -->|"否，丟棄"| S F -->|"是"| M["map 轉換此元素"] M --> T["終端操作處理此元素"] T --> C{"還有元素，且未短路？"} C -->|"是"| S C -->|"否"| E["管線結束"] style F fill:#f0ebfb,stroke:#6d4ad6 style M fill:#f0ebfb,stroke:#6d4ad6 style T fill:#e6f4ec,stroke:#1f9d57,color:#0f6b3a
圖 10-1　元素逐個「縱向」穿過整條管線；短路操作可讓它提早結束

用 peek 觀察實際執行順序，眼見為憑：

Optional<String> result = Stream.of("a", "bb", "ccc", "dddd")
    .peek(s -> System.out.println("filter 檢查: " + s))
    .filter(s -> s.length() > 1)
    .peek(s -> System.out.println("  map  處理: " + s))
    .map(String::toUpperCase)
    .findFirst();   // 短路：找到第一個就停

/* 實際輸出：
   filter 檢查: a          ← a 不通過
   filter 檢查: bb         ← bb 通過
     map  處理: bb         ← 立刻往下走，不等其他元素
   （ccc、dddd 完全沒被碰到——findFirst 已短路結束！）
*/
惰性帶來的兩大好處：① 短路——像 findFirst、limit、anyMatch 找到答案就停，不處理多餘元素； ② 可處理無限流——只要有 limit 收斂，Stream.iterate(...) 這種無限來源也能用。

11. Collectors 收集器

collect() 搭配 Collectors 工具，能把流「收集」成各種形式——這是 Stream 最強大的終端操作。

Collector作用
toList() / toSet()收集成 List / Set
toMap(k, v)收集成 Map
joining(分隔, 前綴, 後綴)字串串接
groupingBy(分類函式)依鍵分組成 Map<K, List<T>>
partitioningBy(條件)依 true/false 分成兩組
counting() / summingInt() / averagingInt()計數 / 加總 / 平均（常作 groupingBy 的下游）
record Person(String name, String city, int age) {}

List<Person> people = List.of(
    new Person("Alice", "Taipei", 30),
    new Person("Bob",   "Taipei", 25),
    new Person("Carol", "Tokyo",  35));

// 依城市分組
Map<String, List<Person>> byCity = people.stream()
    .collect(Collectors.groupingBy(Person::city));

// 各城市人數：groupingBy + 下游 counting
Map<String, Long> countByCity = people.stream()
    .collect(Collectors.groupingBy(Person::city, Collectors.counting()));
// {Taipei=2, Tokyo=1}

// 名字串接
String names = people.stream().map(Person::name)
    .collect(Collectors.joining(", ", "[", "]"));   // [Alice, Bob, Carol]
Alice/TaipeiBob/TaipeiCarol/Tokyo — groupingBy(city) →
Taipei → [Alice, Bob] Tokyo → [Carol]
圖 11-1　groupingBy 把流依分類鍵歸成一個 Map

12. reduce 歸約

reduce 把整條流摺疊（fold）成單一個值：給一個初始值與一個「合併兩個元素」的函式， 它就從頭到尾逐步累積。加總、相乘、求最大值都是它的特例。

flowchart LR I["初始值 0"] --> A1["0 + 1 = 1"] A1 --> A2["1 + 2 = 3"] A2 --> A3["3 + 3 = 6"] A3 --> A4["6 + 4 = 10"] A4 --> R["結果 10"] style I fill:#fcefe2,stroke:#e07b2b,color:#b85f17 style R fill:#e6f4ec,stroke:#1f9d57,color:#0f6b3a
圖 12-1　reduce(0, (a,b)->a+b) 對 [1,2,3,4] 的累積過程
List<Integer> nums = List.of(1, 2, 3, 4);

// 有初始值：保證有回傳值
int sum     = nums.stream().reduce(0, (a, b) -> a + b);   // 10
int product = nums.stream().reduce(1, (a, b) -> a * b);   // 24

// 無初始值：流可能為空，故回傳 Optional
Optional<Integer> max = nums.stream().reduce(Integer::max);  // Optional[4]
初始值（identity）的意義：它必須是該運算的「單位元」——加法用 0、乘法用 1、字串串接用 ""。 這樣即使流是空的，也能安全回傳這個初始值。

13. 平行流（parallelStream）

把 stream() 換成 parallelStream()（或對流呼叫 .parallel()），Stream 就會用 分而治之的方式，把資料切塊丟到多個執行緒（預設用 ForkJoinPool.commonPool()）平行處理，最後合併。

flowchart TB SRC["資料來源"] --> SP["切分成多塊 (split)"] SP --> W1["執行緒 1 處理"] SP --> W2["執行緒 2 處理"] SP --> W3["執行緒 3 處理"] W1 --> MG["合併 (combine)"] W2 --> MG W3 --> MG MG --> R["最終結果"] style SP fill:#f0ebfb,stroke:#6d4ad6 style MG fill:#e6f4ec,stroke:#1f9d57,color:#0f6b3a
圖 13-1　平行流：切分 → 各執行緒獨立處理 → 合併結果
long count = IntStream.rangeClosed(1, 1_000_000)
    .parallel()
    .filter(n -> n % 2 == 0)
    .count();

// 或直接從集合：
list.parallelStream().map(...).collect(...);
平行流不是免費的午餐，用錯反而更慢或出錯。安全使用的前提：
  • 資料量夠大且運算夠重（CPU 密集），否則切分與合併的開銷划不來。
  • 操作無狀態、無共享可變狀態、無副作用——別在 Lambda 裡改外部變數或集合。
  • 用 reduce / collect 累積，不要用 forEach 往共享集合塞東西。
  • 順序敏感的需求要小心：平行下 forEach 不保證順序（需要時用 forEachOrdered）。

14. 常見陷阱與最佳實踐

陷阱：Stream 不能重複使用

Stream<Integer> s = Stream.of(1, 2, 3);
s.forEach(System.out::println);
long c = s.count();   // ❌ IllegalStateException：stream 已被操作或關閉

✅ 最佳實踐

  • 能用方法參考就用，更精簡易讀。
  • 用 Collectors 收集，而非在 Lambda 裡手動累加。
  • 基本型別用 IntStream 等特化流，避免裝箱。
  • Lambda 保持短小、無副作用（純函式）。
  • 善用 短路 操作（findFirst、anyMatch、limit）。
  • 平行流務必實測效能再決定採用。

⚠️ 常見陷阱

  • 把同一條 Stream 用第二次 → 例外。
  • 在 Lambda 內修改外部可變狀態（平行下更危險）。
  • 用 peek 放業務邏輯——惰性／短路下可能不執行。
  • 簡單迴圈硬改成 Stream，反而更難讀。
  • 對基本型別用包裝流，裝箱拖慢效能。
  • 忽略 Optional 直接 get()，可能 NoSuchElementException。
一句話總結：Lambda 讓你把「行為」當參數傳遞，Stream 讓你用「來源 → 中間操作 → 終端操作」的管線 宣告式地處理資料。掌握惰性求值與中間／終端的區別，就掌握了 Stream 的精髓。 建議打開 IDE，把本文每段程式碼都親手跑一次，尤其是第 10 節的 peek 範例——親眼看到執行順序，觀念立刻通透。
